# Разбор кода лабораторной №2 (main.py)

Вся программа лежит в одном файле `main.py`: класс `Database` работает с файлом базы данных, класс `App` рисует окно. Библиотеки только стандартные: `os`, `shutil`, `tkinter`.

## 1. Как устроена база данных

БД — обычный текстовый файл `workout.dat`. Одна запись — одна строка:

`id|название|группа_мышц|нагрузка|флаг`

Пример: `3|Жим лёжа|Грудь|80.0|0`

Флаг `0` — запись есть, флаг `1` — запись удалена. Удаление **логическое**: строка остаётся в файле, но помечается. Физически помеченные строки убираются кнопкой «Сохранить БД».

Поля и их типы: `id` — целое число (ключ), `name` и `muscle` — строки, `load` — вещественное число (всегда хранится как `80.0`, `52.5`).

В памяти хранятся только индексы — это словари (хеш-таблицы), в них нет самих записей:

- `self.index` — `{id: позиция_строки_в_файле}`. Позиция — номер байта, где строка начинается. По ней программа сразу делает `seek` к нужной строке и не читает весь файл;
- `self.name_index`, `self.muscle_index`, `self.load_index` — три словаря для полей name, muscle, load. Каждый хранит `{значение: {id, id, ...}}`, например `{"жим лёжа": {"1", "3"}}`. Название и группа мышц хранятся в нижнем регистре, поэтому поиск не зависит от регистра.

Индексы нужны, чтобы поиск и удаление работали быстро: найти запись — это одно обращение к словарю.

## 2. Класс Database по методам

### Индексы

- `reset_index()` — делает все четыре словаря пустыми.
- `add_to_index(parts, pos)` — записывает в `self.index` позицию строки, а id записи добавляет в множество своего значения в `name_index`, `muscle_index` и `load_index`. `parts` — это строка, разбитая по `|`: `[id, name, muscle, load, флаг]`.
- `remove_from_index(parts)` — обратное действие: убирает запись из всех четырёх индексов.
- `build_index()` — один раз читает файл сверху вниз. Перед каждой строкой запоминает `pos = f.tell()`, читает `readline()`, разбивает по `|`. Если полей 5 и флаг `0`, вызывает `add_to_index`. Пустая строка `""` значит конец файла. Это O(n), но выполняется только при открытии и сохранении.

### Работа с файлом БД

- `create_db(filename)` — создаёт пустой файл (режим `"w"` создаёт или обнуляет файл) и пустые индексы.
- `open_db(filename)` — запоминает имя файла и строит индексы.
- `clear_db()` — то же, что создание, но для текущего файла: он обнуляется.
- `delete_db()` — удаляет файл с диска (`os.remove`) и очищает индексы.
- `save_db()` — копирует в временный файл только строки, которые заканчиваются на `|0` (живые), потом `os.replace` подменяет им исходный файл, и индексы строятся заново, потому что позиции строк сдвинулись.

### Записи

- `get_all()` — читает из файла все живые записи по позициям из `self.index` и возвращает список. Нужен только чтобы показать таблицу на экране.
- `add_record(record_id, name, muscle, load)` — проверяет `record_id in self.index` (так проверяется уникальность ключа), дописывает строку в конец файла (режим `"a"`), запоминает позицию `pos` и вносит запись в индексы.
- `delete_record(record_id)` — берёт позицию из индекса, открывает файл в режиме `"r+"` (чтение и запись), читает строку, возвращается на её начало и пишет её же, но с флагом `1`. Длина строки не меняется, поэтому остальной файл не сдвигается. Потом запись убирается из индексов.
- `update_record(...)` — строки разной длины нельзя безопасно переписать на месте, поэтому старая запись помечается удалённой, а новая дописывается в конец. Ключ при редактировании менять нельзя.
- `find_ids(field, value)` — возвращает список id, у которых поле `field` равно `value`. ID и нагрузка сначала приводятся к единому виду (`007` → `7`, `80,0` → `80.0`), если не получилось — результат пустой. Для `id` проверяется `value in self.index`, для `name`, `muscle` и `load` берётся множество из `name_index`, `muscle_index` или `load_index`. Файл при этом не читается.
- `search(field, value)` — берёт id из `find_ids`, сортирует их по числу, для каждого делает `seek` и читает строку из файла.
- `delete_by_value(field, value)` — находит все id через `find_ids` и удаляет каждый через `delete_record`. Возвращает, сколько записей удалено. Для неключевого поля удаляются все совпавшие записи, как требует задание.

### Backup и экспорт

- `create_backup()` — копирует файл БД в `workout_backup.dat`.
- `restore_backup()` — копирует backup поверх БД и строит индексы заново. Если backup нет, вызывается ошибка.
- `export_csv()` — пишет все записи в `workout_export.csv` с разделителем `;` и кодировкой `utf-8-sig`, чтобы Excel правильно показал русский текст.

## 3. Класс App (окно)

- `create_widgets()` — строит окно: четыре поля ввода (`id_entry`, `name_entry`, `muscle_entry`, `load_entry`), три ряда кнопок, выпадающий список `field_box` для выбора поля поиска и таблицу `ttk.Treeview` с полосой прокрутки. Каждая кнопка создаётся отдельной строкой, так сразу видно, какая кнопка какой метод вызывает.
- `fill_table(records)` и `refresh_table()` — очищают таблицу и заполняют её. У каждой строки таблицы идентификатор (`iid`) равен id записи, поэтому удаление выбранных строк работает по id.
- `on_select()` — при клике по строке копирует её значения в поля ввода, чтобы запись можно было отредактировать.
- `get_fields()` — проверяет ввод: все поля заполнены, ID — целое число, нагрузка — число (запятая допустима), в тексте нет символа `|` (он разделитель в файле). Возвращает готовые значения для записи в БД.
- Обработчики кнопок (`add_record`, `edit_record`, `delete_selected`, `new_db`, `open_db`, `save_db`, `clear_db`, `delete_db`, `backup`, `restore`, `export`) — у каждого свой блок `try / except`: взять данные, при необходимости спросить подтверждение, вызвать метод `Database`, обновить таблицу и показать сообщение. Любая ошибка показывается в окне, программа не падает. Блоки специально повторяются, чтобы каждый обработчик читался отдельно.
- `search` и `delete_by_value` берут номер выбранного поля из `field_box`, а значение — из поля ввода с тем же номером (список `self.entries`).

## 4. Сложность алгоритмов

n — число записей в файле, k — число найденных записей.

| Операция | Сложность | Почему |
| --- | --- | --- |
| Открытие БД | O(n) | один проход по файлу, строятся индексы |
| Добавление | O(1) | проверка ключа в словаре и запись в конец файла |
| Поиск по ключу | O(1) | словарь и один `seek` |
| Поиск по другому полю | O(k log k) | словарь индекса; сортировка k найденных id; от n не зависит |
| Удаление по ключу | O(1) | словарь и запись одного символа |
| Удаление по значению поля | O(k) | k раз удаление по ключу |
| Редактирование | O(1) | удаление и добавление |
| Сохранение БД | O(n) | перезапись файла без удалённых строк |

Вариант «всё линейно» оценивается максимум в 5 баллов. Здесь операции идут через хеш-индексы и не зависят от размера файла, это уровень «константной сложности» (8–10 баллов). На защите стоит сказать самому: открытие и сохранение — O(n), но выполняются редко, а поиск по очень частому значению (например, группа мышц из 8 вариантов) занимает время пропорционально числу найденных записей, потому что их все нужно прочитать.

### 4.1. Временная статистика

Замеры сделаны скриптом `benchmark.py` (лежит рядом с `main.py`), значения — среднее по повторам. На другом компьютере цифры будут другими, важна динамика. Имена повторяются, поэтому на одно имя приходится около n/500 записей (число k в скобках). «Линейный поиск» — полное чтение файла без индекса, как делает простейший вариант.

| n | открытие | добавление | поиск по ID | поиск по name (k) | линейный поиск | удаление по ID | удаление по name (k) | сохранение |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 000 | 20 мс | 0,007 мс | 0,017 мс | 0,029 мс (2) | 0,4 мс | 0,021 мс | 0,05 мс (2) | 14 мс |
| 10 000 | 202 мс | 0,008 мс | 0,017 мс | 0,241 мс (20) | 3,6 мс | 0,022 мс | 0,45 мс (18) | 169 мс |
| 100 000 | 1750 мс | 0,008 мс | 0,019 мс | 2,444 мс (200) | 38,0 мс | 0,024 мс | 4,46 мс (198) | 1644 мс |

- При росте n в 100 раз добавление, поиск по ID и удаление по ID почти не изменились (0,017 → 0,019 мс и 0,021 → 0,024 мс), а линейный поиск замедлился примерно в 95 раз (0,4 → 38,0 мс).
- Поиск и удаление по имени растут вместе с k (2 → 200), а не с размером файла. Даже при 200 найденных записях индекс быстрее линейного поиска примерно в 15 раз.
- Цена индексов — открытие и сохранение: около 1,7 с на 100 000 записей.

## 5. Что изменено в вашем исходном коде

- Весь код теперь в одном файле, названия приведены к обычному виду: `add_record`, `delete_record`, `search`, классы `Database` и `App`.
- Исправлены опечатки `valueerrou` и `valueerroe`: из-за них вместо понятного сообщения программа падала.
- Добавлено то, чего не хватало по заданию: создание, удаление и сохранение БД; удаление по значению любого поля; поиск по выбранному полю; проверка типов при вводе.
- Добавлены индексы `name_index`, `muscle_index`, `load_index`, чтобы поиск и удаление по этим полям не читали весь файл.
- Обработчики кнопок оставлены в том же виде, что в исходном коде: у каждого свой `try / except`, без общих вспомогательных методов. Код получился длиннее, зато каждую кнопку можно прочитать отдельно.

## 6. Ограничения

- Файл открывается в текстовом режиме. Это работает, но надёжнее бинарный режим, где позиции — точное число байт.
- Если имя или группа мышц состоят только из цифр с ведущими нулями (например, «007»), таблица покажет их как число 7, и при клике по строке в поле ввода попадёт «7».
- Индексы занимают память и строятся при открытии: на 100 000 записей около 1,7 с.
- После «Удалить БД» файл удалён, но программа продолжает работать: при добавлении записи файл создастся заново.
- Backup один на все базы (`workout_backup.dat`).
- Одновременная работа нескольких процессов с одним файлом не поддерживается.

## 7. Вопросы к защите

**Почему поиск по ID быстрый?** В памяти словарь «id → позиция в файле», `seek` сразу переходит к нужной строке.

**Как быстро ищется по неключевому полю?** Для каждого поля есть словарь «значение → множество id». Поиск — одно обращение к словарю, дальше читаются только найденные строки.

**Что такое логическое удаление?** Вместо стирания строки меняется один символ-флаг, поэтому файл не нужно переписывать. Лишние строки убирает «Сохранить БД».

**Зачем «Сохранить БД»?** Чтобы физически убрать помеченные строки и не раздувать файл.

**Почему при редактировании запись переезжает в конец файла?** Строки разной длины, новая может не поместиться на старое место.

**Что происходит с индексами при редактировании?** `update_record` вызывает `delete_record` (запись убирается из индексов) и `add_record` (добавляется с новыми значениями), поэтому старые значения не остаются.

**Как проверяется уникальность ключа?** `record_id in self.index` — одно обращение к словарю.

**Почему сложность O(1), а не O(log n)?** Индекс — хеш-таблица (словарь Python), поиск в ней в среднем за константное время; O(log n) было бы у дерева или бинарного поиска.

**Не нарушает ли индекс запрет хранить БД в памяти?** В индексах лежат значения полей, но это служебные хеш-таблицы, которые задание прямо допускает. Записи целиком читаются из файла по позиции, а любое изменение сразу записывается в файл. Будьте готовы это объяснить: именно здесь преподаватель может задать вопрос.

**Что проверено?** Класс `Database` проверялся автоматически: добавление, повторный ключ, поиск по каждому полю, редактирование, удаление по ключу и по значению, сохранение, backup и восстановление, очистка, создание и удаление БД. Само окно с кнопками в моей среде запустить не удалось (нет tkinter), поэтому перед сдачей пройдитесь по кнопкам вручную.
