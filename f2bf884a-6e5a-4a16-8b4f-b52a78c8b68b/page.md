# Отчёт по лабораторной работе №2

**Тема:** файловая база данных «Сервис программ тренировок» (Python, tkinter)

## 1. Задание

Реализовать однотабличную файловую базу данных минимум с четырьмя полями разных типов и одним ключевым полем, с графическим интерфейсом. Требуются создание, открытие, удаление, очистка и сохранение БД; добавление записи с проверкой уникальности ключа; удаление и поиск по значению любого поля (для неключевого — все совпавшие записи); редактирование; backup и восстановление; экспорт в файл стороннего формата. Работа ведётся с файлом БД, а не с массивом записей в памяти. Оценка зависит от сложности алгоритмов.

## 2. Предметная область и структура БД

База хранит справочник упражнений для программ тренировок. Таблица одна, у записи четыре поля:

| Поле | Тип | Назначение |
| --- | --- | --- |
| id | целое число | ключ, уникальный |
| name | строка | название упражнения |
| muscle | строка | целевая группа мышц |
| load | вещественное число | рабочий вес, кг |

**Формат файла** `workout.dat` (UTF-8): одна запись — одна строка

`id|название|группа_мышц|нагрузка|флаг`

Флаг `0` — запись существует, `1` — запись помечена удалённой (логическое удаление). Пример: `3|Жим лёжа|Грудь|80.0|0`.

## 3. Реализованные функции

| Требование | Реализация |
| --- | --- |
| Создание БД | кнопка «Создать БД», метод `create_db` |
| Открытие БД | кнопка «Открыть БД», метод `open_db` |
| Очистка БД | кнопка «Очистить БД», метод `clear_db` |
| Удаление БД | кнопка «Удалить БД», метод `delete_db` (удаляет файл) |
| Сохранение БД | кнопка «Сохранить БД», метод `save_db` (убирает удалённые строки из файла) |
| Добавление с проверкой ключа | `add_record`: проверка `id in index`, ошибка при повторе |
| Удаление по значению поля | `delete_by_value`: по ключу удаляется одна запись, по остальным полям — все совпавшие |
| Поиск по значению поля | `search`: все совпавшие записи выводятся в таблицу |
| Редактирование | `update_record` (запись ищется по ID) |
| Backup и восстановление | `create_backup`, `restore_backup` |
| Экспорт в сторонний формат | `export_csv` (файл `.csv` открывается в Excel) |
| Проверка типов | при вводе: ID — целое, нагрузка — число, в тексте нет символа \` |

## 4. Алгоритмы и сложность

В памяти хранятся только индексы — словари Python (хеш-таблицы):

- `index` — `{id: позиция строки в файле}`;
- `name_index`, `muscle_index`, `load_index` — для полей name, muscle, load словари `{значение: {id, id, ...}}` (название и группа мышц хранятся в нижнем регистре).

Сами записи в память не загружаются: они читаются из файла по позиции (`seek` + `readline`). Исключение — вывод таблицы на экран, как разрешено в задании. Индексы строятся одним проходом при открытии файла.

**Добавление.** Проверка ключа в словаре, запись строки в конец файла, обновление индексов — O(1).

**Удаление.** По позиции из индекса в строке заменяется один символ флага; длина строки не меняется, поэтому файл не сдвигается. Запись убирается из индексов — O(1). Удаление по значению поля находит все id через индекс и удаляет каждый — O(k), где k — число найденных записей.

**Поиск.** По ключу — одно обращение к словарю. По неключевому полю — одно обращение к индексу этого поля, затем чтение k найденных строк из файла — O(k log k) (сортировка id), от размера файла не зависит.

**Редактирование.** Старая запись помечается удалённой, новая дописывается в конец файла — O(1).

**Сохранение.** Файл копируется без удалённых строк и подменяет исходный — O(n).

| Операция | Сложность |
| --- | --- |
| Открытие БД | O(n) один раз |
| Добавление | O(1) |
| Поиск по ключу | O(1) |
| Поиск по неключевому полю | O(k log k), не зависит от n |
| Удаление по ключу | O(1) |
| Удаление по значению поля | O(k) |
| Редактирование | O(1) |
| Сохранение БД | O(n) |

Здесь n — число записей в файле. Для сравнения, вариант «всё линейно» читал бы весь файл при каждом поиске и удалении, то есть O(n).

## 5. Временная статистика

Замеры сделаны скриптом `benchmark.py` на тестовых БД из 1 000, 10 000 и 100 000 записей; значения — среднее по повторам. Имена упражнений повторяются, на одно имя приходится около n/500 записей (число k в скобках). «Линейный поиск» — полный проход по файлу без индекса. На другом компьютере цифры будут другими, важна динамика.

| n | открытие | добавление | поиск по ID | поиск по name (k) | линейный поиск | удаление по ID | удаление по name (k) | сохранение |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 000 | 20 мс | 0,007 мс | 0,017 мс | 0,029 мс (2) | 0,4 мс | 0,021 мс | 0,05 мс (2) | 14 мс |
| 10 000 | 202 мс | 0,008 мс | 0,017 мс | 0,241 мс (20) | 3,6 мс | 0,022 мс | 0,45 мс (18) | 169 мс |
| 100 000 | 1750 мс | 0,008 мс | 0,019 мс | 2,444 мс (200) | 38,0 мс | 0,024 мс | 4,46 мс (198) | 1644 мс |

**Анализ.**

- При росте числа записей в 100 раз время добавления, поиска по ID и удаления по ID почти не изменилось (поиск 0,017 → 0,019 мс, удаление 0,021 → 0,024 мс). Линейный поиск замедлился примерно в 95 раз (0,4 → 38,0 мс). Это подтверждает константную сложность O(1) для операций по ключу.
- Поиск и удаление по имени растут вместе с числом найденных записей k (2 → 200), а не с размером файла. При 200 найденных записях индекс быстрее линейного поиска примерно в 15 раз.
- Цена индексов: открытие и сохранение занимают O(n), около 1,7 с на 100 000 записей. Эти операции выполняются редко.

## 6. Тестирование

Класс `Database` проверялся автоматически (без окна). Проверены сценарии:

- добавление, отказ при повторном ключе;
- поиск по каждому из четырёх полей, без учёта регистра; нагрузки «80», «80.0» и «80,0» находят одну и ту же запись;
- редактирование, в том числе несуществующей записи;
- удаление по ключу и по значению неключевого поля (удаляются все совпавшие);
- сохранение: файл уменьшается, после повторного открытия данные те же, индексы совпадают;
- backup, восстановление, очистка, создание и удаление БД;
- экспорт в CSV.

Окно с кнопками в среде проверки запустить не удалось (нет библиотеки tkinter), поэтому интерфейс нужно пройти вручную перед сдачей.

## 7. Ограничения

- Файл открывается в текстовом режиме; надёжнее бинарный, где позиции — точное число байт.
- Индексы занимают память и строятся при открытии, что для очень больших БД занимает время.
- Ключ при редактировании менять нельзя.
- Backup один на все базы (`workout_backup.dat`).
- Одновременная работа нескольких процессов с одним файлом не поддерживается.

## 8. Вывод

Реализована файловая БД с полным набором операций из задания. Добавление, поиск и удаление по ключу выполняются за константное время, поиск и удаление по неключевым полям не зависят от размера файла благодаря хеш-индексам, а данные хранятся и изменяются только в файле. Замеры подтверждают теоретическую оценку сложности.
